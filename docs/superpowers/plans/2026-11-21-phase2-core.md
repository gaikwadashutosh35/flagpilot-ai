# Phase 2 Core Product Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the FlagPilot landing CTA (Flagsmith-controlled), the deterministic copilot whose plan approval is the real conversion, and the experiment status page. Create the real Flagsmith flag and metric, each with separate owner approval.

**Architecture:** A single React SPA in `apps/web` with three routes. Flagsmith is used only through the documented SDK:
- the `FlagsmithProvider` options set `identity` and `enableEvents: true`;
- `useExperiment` runs only in the CTA's inner component;
- `useFlags` and `useFlagsmithLoading` read state everywhere else;
- events go through the `flagsmith` singleton.

Pure logic (identity, plan generator, config preview, event guards) lives in small tested modules. Flagsmith resources are created from the Claude session with the CLI, never from the browser.

**Tech Stack:** React 19.3, Vite 8.3, TypeScript 7.0.2 (fallback ~6.0), Oxlint, Tailwind 4.3 + `@tailwindcss/vite`, shadcn CLI 4.23, `react-router` 8.5.2, `@flagsmith/flagsmith` 12.5.0, Vitest 5.1 + jsdom 31 + Testing Library (react 16.3, jest-dom 8, user-event 14), Playwright 1.65.

**Spec:** `docs/superpowers/specs/2026-11-21-phase2-core-design.md`. Read it with this plan; § references below point to it.

**Execution routing** (`docs/MODEL_ROUTING.md`):
- Tasks marked **[feature-implementer]** or **[test-engineer]** go to those Sonnet agents.
- Tasks marked **[main session]** are run by the coordinator and include owner approval gates.
- Security review in Task 10 goes to **[security-reviewer]** (Opus).

All paths are relative to `apps/web/` unless they start with `docs/` or the repo root is stated.

## Global Constraints

- Flag key `flagpilot_onboarding_cta`. Variant keys `control` and `benefit_copy`.
- CTA copy: `control` is "Create your first experiment". `benefit_copy` is "Launch an experiment in minutes".
- Events exactly `flagpilot_demo_completed` (primary) and `flagpilot_primary_cta_clicked` (diagnostic).
- Flagship question exactly "Does benefit-oriented CTA copy increase demo completion?". Its hypothesis is exactly "Benefit-oriented CTA copy increases genuine demo completion."
- Identity: `fp_` + `crypto.randomUUID()`, in `localStorage['flagpilot.visitorId']`.
- Guards: `localStorage['flagpilot.ctaSeenFor']` and `localStorage['flagpilot.completedFor']`, each holding a visitor ID.
- Only env var: `VITE_FLAGSMITH_ENVIRONMENT_KEY` (client key). No other `VITE_*` variable may hold a key or secret.
- `useExperiment` is called only in `src/features/playground/CtaExposure.tsx`.
- No `dangerouslySetInnerHTML`. No fake numbers or results anywhere.
- Flag key and event-name regex: `^[a-z][a-z0-9_]{2,49}$`. Question 10–500 chars after trim. Success field ≤200 chars.
- No Flagsmith write without its own owner approval in chat, showing the target (FlagPilot / Development) and the exact command.
- Tests import `describe/it/expect/vi` from `vitest` (no globals). The setup file calls `afterEach(cleanup)`.
- Commit at the end of each task with the message given. Never stage `.env.local`, `node_modules`, `dist`, or the root `MODEL_ROUTING.md`/`SKILL.md`.

## Review Focus

1. **React StrictMode double-mounts in dev.** Mounting the CTA twice must not send click/complete events. `markCtaSeen` must be idempotent. (Task 3: StrictMode render test.)
2. **localStorage throws or is unavailable** (private mode, blocked storage). Identity, `markCtaSeen` and `completeDemo` must not crash; they fall back to in-memory values. (Task 2: storage-throws tests.)
3. **Question with no ASCII letters** (emoji-only, symbols, non-Latin). `generatePlan` must still return a plan whose `flagKey` passes the regex. (Task 5: emoji and Devanagari inputs.)
4. **Double-click on Approve.** Must send `flagpilot_demo_completed` once and must not show two Done states. (Task 6: double-click test.)
5. **"Start another plan", then approve again.** This must not send a second conversion, and Done must say "already counted for this visitor". (Task 6: re-approve test.)
